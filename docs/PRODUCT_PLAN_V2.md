# 책결 제품 기획서 v2

기준일: 2026-08-21
제품 상태: 기능형 프로토타입 완료, 외부 인프라 연결 전

## 1. 제품 한 줄 정의

책결은 가까운 사람끼리 서로 다른 책을 읽으면서도 “지금 무엇을, 얼마나 읽고 있는지”를 부담 없이 나누는 비공개 중심 소셜 독서 앱이다.

## 2. 해결하려는 문제

독서는 가치 있는 활동이지만 과정이 잘 보이지 않는다. 완독 리뷰 중심 서비스에서는 읽는 도중의 작은 진전과 생각이 사라지고, 메신저 독서 모임에서는 진척·메모·스포일러가 한 대화방에 섞인다. 공개 SNS는 반응과 비교 압력이 크다.

책결은 다음 세 가지를 동시에 해결한다.

1. 기록 마찰: 책 추가와 진척 기록을 30초 안에 끝낸다.
2. 관계의 단절: 완독이 아니라 읽는 과정의 마일스톤으로 친구와 이어진다.
3. 공개 부담과 스포일러: 친구·그룹 단위 공개와 독서 위치 기반 잠금을 기본으로 제공한다.

## 3. 핵심 가설

“친한 사람이 책을 펼쳤다는 가벼운 신호와 마일스톤에 대한 작은 응원은, 순위·경쟁 없이도 독서 지속성과 관계감을 높인다.”

가설이 깨지면 사용자는 개인 기록만 하고 피드를 보지 않거나, 친구를 연결해도 서로 반응하지 않는다. 따라서 단순 가입자 수보다 연결된 양쪽의 주간 행동을 핵심 지표로 삼는다.

## 4. 목표 사용자

### 4.1 1차 사용자

- 각자 다른 책을 읽지만 독서 근황을 나누고 싶은 친구·연인·가족
- 종이책 중심이며 독서 기록 앱의 복잡한 입력을 부담스러워하는 사람
- 공개 독서 SNS보다 2~20명의 안전한 관계를 선호하는 사람

### 4.2 2차 사용자

- 소규모 사내·학교·지역 독서 모임
- 오디오북·전자책·종이책을 함께 기록하는 다형식 독자
- 스포일러 없이 같은 책을 느슨하게 같이 읽고 싶은 모임

## 6. 제품 원칙

1. 친밀한 관계 우선: 일방향 팔로우보다 상호 수락 친구와 비공개 그룹이 먼저다.
2. 과정 우선: 완독 리뷰보다 시작·25·50·75·완독과 현재 독서 상태를 다룬다.
3. 비공개 기본: 공개 범위와 진척 정밀도를 책별로 바꿀 수 있다.
4. 비교 최소화: 리더보드·친구 순위·강제 스트릭 경고를 만들지 않는다.
5. 스포일러 안전: 대화는 독서 위치를 이해하고 아직 도달하지 않은 내용을 잠근다.
6. 기록은 견고하게: 오프라인에서도 먼저 저장하고 재연결 시 멱등 동기화한다.

## 8. 핵심 사용자 흐름

### 흐름 A: 첫 가치 경험

로그인 → 책 검색/스캔 → 읽는 중 등록 → 친구 초대 → 25% 기록 → 친구가 응원

목표: 신규 사용자의 50%가 첫 세션에 책을 추가하고, 초대를 받은 사용자의 35%가 24시간 내 수락한다.

### 흐름 B: 일상 기록

기록 탭 → 책 선택 → 타이머 시작 → 진척·메모 → 저장 → 마일스톤이면 선택 범위에 공유

목표: 서버 연결 상태와 무관하게 30초 내 완료, 중복 기록 0, 동기화 실패가 UI에서 사라지지 않음.

### 흐름 C: 안전한 대화

친구 피드 → 한마디 → 공개 조건 선택 → 상대 진척 미달 시 잠금 → 도달 후 자동 공개

목표: 스포일러 신고율 1,000 댓글당 1건 미만.

### 흐름 D: 소그룹

그룹 생성 → 링크 초대 → 책별 공개 범위를 그룹으로 지정 → 구성원만 피드·댓글 확인

목표: 생성 그룹의 60%가 7일 안에 2명 이상과 첫 공유를 만든다.

## 9. 정보 구조

- 함께: 실시간 독서 상태, 주간 리포트, 친구/그룹 피드, 응원·댓글
- 기록: 다권 선택, 타이머, 진척, 메모, 동기화 상태
- 나: 프로필, 책장, 통계·목표, 테마, 공개 범위, 알림, 데이터·계정
- 보조 화면: 검색·스캔·직접 등록, 책 상세, 친구, 그룹, 초대, 댓글

하단 탭을 세 개로 제한한 이유는 첫 가치인 “보기·기록하기·관리하기”를 한 번의 탭 전환 안에 두기 위해서다.

## 10. 공개·스포일러 정책

- 기본 공개 범위는 친구이며 사용자가 나만/친구/그룹/전체로 바꿀 수 있다.
- 그룹 공개는 해당 그룹 구성원과 작성자만 볼 수 있다.
- 차단 관계는 양방향으로 피드·댓글·친구 연결을 차단한다.
- 진척 정밀도는 숨김/마일스톤/정확한 값으로 분리한다.
- 위치 잠금 댓글은 작성자와 해당 위치 이상을 읽은 사용자에게만 본문을 노출한다.
- 신고는 삭제가 아니라 검토 대기 데이터로 남고 운영자가 처리한다.

## 11. 알림 정책

- 즉시 후보: 친구 연결 수락, 내 기록의 응원·댓글
- 선택 후보: 친구의 마일스톤
- 묶음 후보: 일반 독서 소식의 하루 한 번 다이제스트
- 조용한 시간에는 개인별 종료 시각까지 전달 큐를 지연한다.
- 알림 탭은 `/friends`, `/comments/{eventId}` 같은 내부 경로만 허용한다.
- 사용 중지·만료 토큰은 비활성화하고 최대 5회 지수 재시도한다.

## 12. 성공 지표

### North Star

주간 상호 독서 연결 수: 같은 친구 쌍 또는 그룹에서 한쪽이 기록하고 다른 쪽이 7일 안에 피드 확인·응원·댓글 중 하나를 수행한 고유 연결 수.

### 퍼널

- 가입 → 첫 책 등록률
- 첫 책 등록 → 첫 기록률
- 초대 생성 → 수락률
- 연결 완료 → 7일 내 양쪽 기록률
- 피드 노출 → 응원/댓글률

### 품질 가드레일

- 진척 기록 API 성공률 99.9% 이상
- 오프라인 큐 24시간 초과 비율 0.5% 미만
- 피드 공개 범위 사고 0건
- 푸시 거부 이후 재요청 0건
- 신고 처리 SLA 24시간 이내 95%
- 앱 비정상 종료 없는 세션 99.5% 이상

## 13. 출시 단계

### 단계 0: 내부 알파

- 현재 코드와 로컬/스테이징 DB
- 팀 10~20명, 다권 기록·그룹 권한·오프라인·스포일러 테스트
- 종료 조건: P0 데이터/권한 결함 0, 7일 연속 사용 가능

### 단계 1: 초대형 비공개 베타

- Supabase·Kakao·EAS·Universal Links·운영자 접근망·모니터링·법적 문서 연결
- 100~300명, 친구 쌍과 5명 이하 그룹 중심
- 종료 조건: 첫 책 등록률 60%, 초대 수락률 35%, W2 유지율 25%

### 단계 2: 공개 베타

- 구현된 신고 운영·계정 완전 삭제의 실제 SLA 검증, 가져오기, 검색·태그 개선
- 단계적 스토어 공개와 장애 대응 온콜

### 단계 3: 성장

- 그룹 일정·지정 도서·그룹 피드, OCR, 월간/연간 카드, 신뢰 기반 추천
- 추천은 친구 관계와 명시적 공개 데이터만 사용한다.

## 14. 수익화 가설

첫 출시에서는 무료 핵심 경험과 신뢰 형성이 우선이다. 유료화 후보는 관계 기능을 잠그지 않는 항목만 검토한다.

- 고급 통계·연간 회고 테마
- OCR/인용문 정리와 고급 내보내기
- 대규모 그룹 운영 도구
- 추가 커스텀 테마

친구 연결, 기본 그룹, 기록, 스포일러 보호, 데이터 내보내기는 무료 핵심으로 유지한다.
