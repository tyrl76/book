# 실사용 개선 3회 루프

기준일: 2026-09-01

대상: Android·웹 공통 책 탐색, 책장, 독서 기록 흐름

실기기와 Android 에뮬레이터가 연결되지 않았고 새 브라우저 세션은 로그인 보호 상태였다. 계정 보호를 우회하거나 운영 데이터를 만들지 않고, 사용자의 실제 행동 순서대로 화면 상태·API 계약·로컬 상태를 대조한 뒤 각 회차마다 구현과 정적·서버 검증을 반복했다.

| 회차 | 실제 사용자 행동 | 발견한 불편·실패 현상 | 반영한 개선 | 회차 검증 |
|---|---|---|---|---|
| 1 | 책 검색 → 이미 담은 책을 다시 발견 → 읽기 시작 | 검색 결과가 책장 상태를 몰라 다시 입력해야 하고, `읽고 싶음` 판본은 중복 회차가 생길 수 있음 | 독서 회차 응답에 ISBN을 포함하고 검색 카드에 현재 상태·상세·이어 읽기 동작 표시, 서버에서 읽고 싶음/읽는 중/멈춤 중복 생성 차단 | 관련 Go 테스트, TypeScript, Expo lint |
| 2 | 내 책장 → 특정 책 선택 → 기록 화면 이동 | 상세 화면을 거쳐야 하고 기록 화면이 전달된 회차 ID를 읽지 않아 다른 책이 선택될 수 있음 | 책장 카드에 시작·계속·기록 버튼 추가, `record?runID=`로 지정 회차 직접 선택 | TypeScript, Expo lint |
| 3 | 타이머 시작 → 진척/메모 입력 → 공개 범위 확인 → 저장 | 변경 없는 빈 기록 저장 가능, 실제 설정과 무관한 친구 공개 문구, 웹 확인창 동작 차이 | 의미 있는 변경이 있을 때만 저장, 실제 공개 범위·자동 공유 미리보기, 타이머 초기화·책 전환 공통 확인창 | TypeScript, Expo lint, 공통 웹 번들 |

## 남겨 둔 후속 관찰 항목

- 실기기에서 키보드가 열린 상태의 기록 버튼 가시성과 한 손 조작 거리를 확인한다.
- 실제 책장 50권 이상에서 카드 빠른 동작과 삭제 버튼의 시각적 밀도를 확인한다.
- 완독·중단 판본의 재독 시작 문구와 회차 비교 화면은 충분한 재독 데이터가 쌓인 뒤 별도 검증한다.
